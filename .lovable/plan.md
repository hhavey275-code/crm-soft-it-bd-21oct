# External CRM (admiki) — Semi-Auto টপ-আপ (API ছাড়া)

## সংক্ষেপে উত্তর

হ্যাঁ, এটা করা যায়। API ছাড়াই semi-auto সম্ভব, কারণ admiki-র লগইন আমাদের অ্যাডমিনের ব্রাউজারেই আছে। কৌশলটা হলো: অ্যাডমিন approve চাপলে admiki-র পেজ খুলবে এবং একটা ছোট ব্রাউজার হেল্পার (Chrome extension) ওই পেজে গিয়ে অ্যাড অ্যাকাউন্ট খুঁজে, অ্যামাউন্ট বসিয়ে টপ-আপ ফর্মটা পূরণ করে দেবে। অ্যাডমিন শুধু শেষ কনফার্ম বাটনে চাপ দেবে (বা চাইলে সেটাও অটো)।

সার্ভার থেকে এটা করা যায় না (আমাদের সার্ভারে ওদের লগইন সেশন নেই), তাই কাজটা অ্যাডমিনের ব্রাউজারেই হবে — এতে ওদের নিয়মও ভাঙে না, কারণ লগইন করা মানুষ নিজেই কাজটা অনুমোদন করছে।

## কীভাবে কাজ করবে

```text
Client টপ-আপ চায়  →  ওয়ালেট কাটা হয়, request আসে
      ↓
Admin dashboard: "Approve & Top-Up" বাটন
      ↓
admiki tab খোলে (অ্যাকাউন্ট ID + অ্যামাউন্ট সাথে যায়)
      ↓
ব্রাউজার হেল্পার: অ্যাকাউন্ট সার্চ → টপ-আপ ফর্ম → অ্যামাউন্ট বসানো
      ↓
Admin কনফার্ম (বা অটো-কনফার্ম চালু থাকলে নিজেই)
      ↓
হেল্পার ফলাফল আমাদের সিস্টেমে ফেরত পাঠায় → request "completed" + transaction
```

## যা বানানো হবে

1. **অ্যাডমিন সাইডে "Approve & Top-Up"**: এখনকার External Top-Up Requests সেকশনে একটাই বাটন — চাপলে admiki-র সঠিক পেজ নতুন ট্যাবে খোলে, সাথে অ্যাকাউন্ট ID ও অ্যামাউন্ট থাকে।
2. **ছোট ব্রাউজার হেল্পার (Chrome extension)**: শুধু আমাদের অ্যাডমিনরা একবার ইনস্টল করবে। এটি admiki পেজে অ্যাকাউন্ট সার্চ করে, টপ-আপ বক্সে অ্যামাউন্ট বসায়, স্ক্রিনে একটা ছোট বার দেখায় ("Client X, $50 — Confirm")। সেটিংসে "নিজেই কনফার্ম করে দাও" চালু/বন্ধ করা যাবে।
3. **ফল ফিরে আসা**: টপ-আপ সফল হলে হেল্পার আমাদের সিস্টেমে জানায় → request নিজে নিজেই completed, ট্রানজেকশনে উঠে যায়। ব্যর্থ হলে কারণসহ pending থাকে, নোটিফিকেশন ও সাউন্ড বাজে।
4. **একাধিক CRM সাপোর্ট**: প্রতি CRM-এর জন্য আলাদা সেটিং (লিংক, কোন ঘরে অ্যাকাউন্ট বসবে, কোন ঘরে অ্যামাউন্ট)। নতুন CRM এলে শুধু সেটিং যোগ করলেই চলবে, কোড বদলাতে হবে না।
5. **সেফটি**: ডাবল টপ-আপ ঠেকানো, প্রতিটা প্রচেষ্টার লগ (কে, কখন, কত, ফল কী), এবং হেল্পার কাজ না করলে এখনকার ম্যানুয়াল কপি-পেস্ট ব্যবস্থা অপরিবর্তিত থাকবে।

## সীমাবদ্ধতা (আগে জেনে রাখা ভালো)

- অ্যাডমিনের ব্রাউজারে admiki-তে লগইন থাকতে হবে এবং হেল্পার ইনস্টল থাকতে হবে; মোবাইল থেকে অটো হবে না (মোবাইলে পুরনো ম্যানুয়াল পথ থাকবে)।
- admiki তাদের পেজের ডিজাইন বদলালে হেল্পারের ছোট আপডেট লাগবে — সেটা দ্রুত করা যায়।
- ক্লায়েন্টের জন্য সম্পূর্ণ অটো (অ্যাডমিন ছাড়া) তখনই সম্ভব হবে, যদি ওরা কোনোদিন API দেয়।

## ধাপে ধাপে ডেলিভারি

- ধাপ ১: অ্যাডমিন সাইডে "Approve & Top-Up" বাটন + প্রতি CRM সেটিং + ফল ফেরত নেওয়ার endpoint।
- ধাপ ২: admiki-র জন্য ব্রাউজার হেল্পার (ফর্ম পূরণ + কনফার্ম + ফল পাঠানো)। এর জন্য admiki-র টপ-আপ পেজের ২-৩টা স্ক্রিনশট লাগবে।
- ধাপ ৩: বাকি CRM-গুলোর জন্য একই হেল্পারে কনফিগ যোগ করা।

## কারিগরি নোট

- হেল্পার হবে Manifest V3 Chrome extension: content script admiki ডোমেইনে চলবে, আমাদের সাইট থেকে ট্যাব খোলার সময় query param-এ `request_id`, `account_id`, `amount` যাবে।
- ফল ফেরত নেওয়ার জন্য `src/routes/api/public/external-topup-callback.ts` — শেয়ার্ড সিক্রেট হেডার দিয়ে যাচাই, তারপর `complete_external_topup` RPC কল।
- `external_topup_requests`-এ নতুন কলাম: `crm_provider`, `provider_txn_id`, `auto_attempts`, `last_error`; স্ট্যাটাসে `failed` যোগ।
- CRM কনফিগ (লিংক, সিলেক্টর ম্যাপ) DB-তে JSON হিসেবে, অ্যাডমিন সেটিংস থেকে সম্পাদনযোগ্য — যাতে সিলেক্টর বদল কোড ছাড়াই আপডেট হয়।
- ওয়ালেট কাটা/রিফান্ডের লজিক অপরিবর্তিত; শুধু completion অটোমেটিক হবে। Idempotency key দিয়ে দুইবার টপ-আপ ঠেকানো হবে।
