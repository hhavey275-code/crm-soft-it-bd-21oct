# External CRM (admiki) থেকে অটো টপ-আপ

## সংক্ষেপে উত্তর

হ্যাঁ, technically সম্ভব — কিন্তু একটাই আসল শর্ত: admiki-র দিক থেকে একটা top-up করার উপায় (API/টোকেন) পাওয়া। আপনি বলেছেন ওরা API দেয় না, তাই প্রথম ধাপ হবে ওদের কাছ থেকে অনুমতি + অ্যাক্সেস চাওয়া। অ্যাক্সেস পেলে আমাদের সিস্টেম নিজেই ওদের ওয়ালেট থেকে ওই অ্যাড অ্যাকাউন্টে ডলার পাঠাতে পারবে, আর কেউ ম্যানুয়ালি ওদের প্যানেলে ঢুকতে হবে না।

গুরুত্বপূর্ণ: আমাদের পক্ষ থেকে ওদের প্যানেলে লগইন করে রোবট দিয়ে বাটন চাপার কৌশল আমরা করব না — ওটা ওদের শর্ত ভাঙতে পারে, অ্যাকাউন্ট বন্ধ হওয়ার ঝুঁকি আছে, আর একটা ডিজাইন বদলালেই ভেঙে যায়। তাই পরিকল্পনা দুই ধাপে সাজানো।

## ধাপ ১ — admiki থেকে যা চাইতে হবে (আপনার কাজ)

ওদের সাপোর্টে এই কথাগুলো জিজ্ঞেস করুন:
- আমাদের রিসেলার অ্যাকাউন্ট থেকে API দিয়ে ad account-এ টপ-আপ করার সুযোগ আছে কি?
- থাকলে: API key/টোকেন, endpoint, আর কোন ফিল্ড লাগে (ad account ID, amount)।
- টপ-আপ সফল হয়েছে কি না সেটা যাচাই করার কোনো উপায় আছে কি (status/transaction ID)?
- ওদের ওয়ালেট ব্যালেন্স দেখার কোনো উপায় আছে কি?

উত্তর পেলে আমাকে জানালেই ধাপ ২ চালু করা যাবে।

## ধাপ ২ — অ্যাক্সেস পেলে আমাদের সিস্টেমে যা বানানো হবে

একাধিক CRM আছে, তাই একটা সাধারণ কানেক্টর বানানো হবে — প্রতিটা CRM আলাদা করে সেট করা যাবে:

1. অ্যাডমিন সেটিংসে প্রতি CRM-এর জন্য: নাম, লিংক, API address, key (গোপনে সংরক্ষিত), আর "অটো টপ-আপ চালু/বন্ধ" সুইচ।
2. প্রতিটা ad account-এ কোন CRM ব্যবহার হবে তা নির্বাচন করা যাবে (এখনকার external লিংকের জায়গাতেই)।
3. ক্লায়েন্ট টপ-আপ বাটনে চাপলে:
   - এখনকার নিয়মেই ওয়ালেট/due limit যাচাই হবে (main বা secondary, রেট সমন্বয় সহ),
   - ব্যালেন্স কাটা হবে,
   - সিস্টেম সাথে সাথে CRM-এ টপ-আপ পাঠাবে,
   - সফল হলে অ্যাকাউন্ট "completed" হয়ে ট্রানজেকশনে উঠে যাবে; ক্লায়েন্ট সাথে সাথেই confirmation দেখবে।
4. CRM যদি না নেয় (ব্যালেন্স কম, নেটওয়ার্ক সমস্যা, ভুল অ্যাকাউন্ট):
   - রিকোয়েস্ট "pending/failed" হয়ে অ্যাডমিন সেকশনে চলে আসবে, কারণসহ,
   - নোটিফিকেশন ও সাউন্ড বাজবে,
   - অ্যাডমিন হাতে করে দিতে পারবে (এখনকার লিংক-ও-কমপ্লিট বাটন থাকবে), অথবা reject করলে টাকা ফেরত যাবে।
5. একই রিকোয়েস্ট দুইবার পাঠানো আটকানোর ব্যবস্থা, এবং প্রতিটা কলের লগ (কখন, কত, ফল কী) রাখা হবে।
6. CRM ওয়ালেট ব্যালেন্স দেখার সুযোগ থাকলে অ্যাডমিন ড্যাশবোর্ডে সেটাও দেখানো হবে, যাতে ব্যালেন্স কমে গেলে আগেই টের পাওয়া যায়।

ফলাফল: বেশিরভাগ টপ-আপ নিজে নিজেই হবে, আর যেগুলো আটকাবে সেগুলোই শুধু অ্যাডমিনের কাছে আসবে — এখনকার ম্যানুয়াল সিস্টেম সেফটি নেট হিসেবেই থাকবে।

## যদি admiki কোনোভাবেই অ্যাক্সেস না দেয়

তিনটা বিকল্প থাকবে:
- এখনকার এক-ক্লিক ম্যানুয়াল ব্যবস্থাই রাখা (দ্রুত, নিরাপদ)।
- ওদের সাথে কথা বলে আমাদের জন্য একটা ছোট endpoint বানিয়ে নেওয়া (reseller হিসেবে অনেকেই রাজি হয়)।
- ওই অ্যাকাউন্টগুলো ধীরে ধীরে আমাদের নিজের API-connected অ্যাকাউন্টে সরিয়ে নেওয়া, যেখানে অটো টপ-আপ আগেই কাজ করে।

## কারিগরি নোট

- কল হবে সার্ভার সাইড থেকে (TanStack server function), key কখনো ব্রাউজারে যাবে না; key সংরক্ষণ হবে project secrets-এ, CRM প্রতি আলাদা নামে।
- `external_topup_requests`-এ নতুন কলাম: `crm_provider`, `provider_txn_id`, `auto_attempts`, `last_error`; স্ট্যাটাসে `failed` যোগ।
- বর্তমান `request_external_topup` / `complete_external_topup` / `reject_external_topup` RPC-গুলোই ব্যবহার হবে; ওয়ালেট কাটা ও রিফান্ডের লজিক অপরিবর্তিত।
- Idempotency key দিয়ে ডাবল টপ-আপ ঠেকানো হবে; প্রতিটা কলের রেসপন্স `system_logs`-এ থাকবে।
- ব্রাউজার অটোমেশন (হেডলেস লগইন) এই সার্ভার রানটাইমে চলে না, তাই সেটা পথ হিসেবে ধরা হচ্ছে না।
